# Architecture Decision Record (ADR)

# ADR-006: Monorepo Architecture for Shared Ecosystem

- **Estado:** Aprobado
- **Fecha:** 2026-07-12
- **Autor:** Antigravity (AI Architect)

---

# 1. Contexto (Context)
Campus Arena está compuesto por una aplicación frontend (Next.js), una API backend (NestJS) y, en el futuro, paneles adicionales (para streamers, bots de Discord, app móvil). Varias entidades (como el modelo de datos `Tournament` o las interfaces de los adaptadores de juego) y componentes visuales del Design System deben ser compartidos. Mantener repositorios separados ralentiza el desarrollo y genera duplicación e inconsistencia en los tipos de datos.

---

# 2. Decisión (Decision)
Hemos elegido consolidar todo el ecosistema de Campus Arena en una arquitectura de **Monorepo** único utilizando espacios de trabajo (workspaces) nativos.

---

# 3. Justificación (Justification)

1. **Única Fuente de Verdad (Single Source of Truth):** Compartimos código común instantáneamente. Modificar una interfaz en `@campus-arena/types` actualiza de forma automática el tipado en la API y el frontend Next.js.
2. **Consistencia en el Setup:** Toda la suite de calidad (TSConfig, Prettier, ESLint) se define una sola vez en `@campus-arena/config` y es heredada por todas las aplicaciones.
3. **Gestión de Dependencias Simplificada:** Se descargan e instalan dependencias comunes en un único proceso, optimizando el espacio del host de desarrollo y de compilación.

---

# 4. Consecuencias (Consequences)

### Positivas
- Refactorización de interfaces y tipos extremadamente rápida y segura.
- Pipeline de CI/CD único y unificado para todo el producto.
- Facilidad para incorporar nuevas aplicaciones (bots, app móvil, landing secundaria) reutilizando código existente.

### Negativas
- El tamaño del repositorio crece con mayor rapidez (mitigable no subiendo binarios ni dependencias de node_modules).
- Curva de aprendizaje adicional en la orquestación de tareas paralelas (ej. correr dev de api y web simultáneamente).
