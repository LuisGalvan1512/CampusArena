# Architecture Decision Record (ADR)

# ADR-001: NestJS as Backend API Framework

- **Estado:** Aprobado
- **Fecha:** 2026-07-12
- **Autor:** Antigravity (AI Architect)

---

# 1. Contexto (Context)
Campus Arena requiere una API sólida, escalable y mantenible para gestionar torneos de eSports interuniversitarios. El backend interactúa con múltiples videojuegos (vía APIs y adaptadores), base de datos transaccional, autenticación y notificaciones en tiempo real (WebSockets). Necesitamos una arquitectura de servidor ordenada que obligue a los desarrolladores y agentes de IA a seguir el mismo estándar de estructuración.

---

# 2. Decisión (Decision)
Hemos elegido **NestJS** como el framework de backend principal para construir la API REST y gestionar las conexiones de WebSockets. 

Esta elección se complementa con **TypeScript** como lenguaje único en el backend.

---

# 3. Justificación (Justification)

1. **Estructura Modular Out-of-the-box:** NestJS organiza el código mediante módulos (`@Module`), controladores (`@Controller`) y servicios (`@Injectable`). Esto evita el "código espagueti" común en Express y encaja de forma perfecta con los *Bounded Contexts* definidos en Domain-Driven Design (DDD).
2. **Inyección de Dependencias (IoC):** El sistema nativo de inversión de control de NestJS simplifica las pruebas unitarias y permite desacoplar los servicios de persistencia (Prisma) de la lógica de negocio.
3. **Ecosistema Completo:** NestJS provee soporte oficial y configuraciones listas para WebSockets, OpenAPI (Swagger), autenticación (Passport) y manejo de validaciones (ValidationPipe).
4. **Soporte TypeScript Nativo:** Al usar TypeScript de extremo a extremo, compartimos los tipos de datos comunes en el monorepo sin tener que reescribir interfaces en el frontend y backend.

---

# 4. Consecuencias (Consequences)

### Positivas
- Código altamente predecible y consistente para desarrolladores humanos y agentes de IA.
- Separación de responsabilidades natural.
- Documentación de API auto-generada vía Swagger con decoradores.

### Negativas
- Curva de aprendizaje inicial ligeramente más alta para desarrolladores que solo conocen Express vanilla.
- Mayor cantidad de archivos iniciales (boilerplates de módulos).
